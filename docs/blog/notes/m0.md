## Task 1: bringing in shaped-core (2026-11-16)

- Pinned shaped-core `8c853df` as a submodule; `SC_LIBRARIES=clean-core;typed-geometry`.
- **Snag 1: C compiler.** shaped-core's vendored C libraries (xxhash, zstd, ...)
  enable CMake's C language. The presets named only a C++ compiler, so on Windows
  CMake picked `clang.exe` (GNU-style options) for C and fed it MSVC flags
  (`/DWIN32` → "no such file or directory"). Fix: name `CMAKE_C_COMPILER` in every
  preset.
- **Snag 2: Clang version.** Ubuntu 24.04's default Clang 18 has no
  `std::hardware_destructive_interference_size` (Clang added it in 19).
  shaped-core builds with Clang 21. Fix: a configure-time check that fails with a
  clear message, and CI on `ubuntu-26.04` with `clang++-21`.
- **Snag 3: an upstream bug.** `clean-core/thread/thread.cc` uses an unqualified
  `isize` in the Linux thread-name code. The macOS branch was fixed in
  `cd0f58591`; the Linux branch wasn't. Not patched in the submodule; worked
  around with a force-included one-liner (`cmake/shaped_core_workarounds.h`).
  Upstream's own Linux CI is red at `8c853df`, so it's their bug, not how Vespera
  consumes the library. To be reported to the authors.
- **Snag 4: Windows CI never passed.** Every win-clang run in the history was
  cancelled or failed, and the run on `de3b863` sat "in progress" for hours. CI
  now enters the VS developer environment through `vcvars64` (an inline script,
  not a third-party action). Whether the hang is gone is unverified until CI
  runs.
- **Inherited flags.** Linking clean-core added these to Vespera's own compile
  lines through `shaped-core::build-config`:
  - `-march=x86-64-v3`: AVX2 is now the minimum CPU
  - `-ffp-contract=off`
  - `-fno-omit-frame-pointer`

  Worth a paragraph. The x86-64-v3 floor is a shipping decision too.
- **ARM64 CI** moved from a qemu cross build to a native `ubuntu-26.04-arm`
  runner, matching how shaped-core tests it. The cross preset and the death
  tests' emulator plumbing were deleted.
- **Snag 4 resolved.** The Windows hang was the Debug CRT: `abort()` shows a
  modal Abort/Retry/Ignore box when output isn't a console. Fixed with
  `_set_abort_behavior(0, _WRITE_ABORT_MSG | _CALL_REPORTFAULT)` before aborting.
  `death_assert_fires` went from 2.7 s to 0.03 s locally, and CI went green for
  the first time.
- ASan: `SC_MIMALLOC=OFF`, because LeakSanitizer can't see mimalloc's memory.
